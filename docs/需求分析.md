# 内容工厂需求分析

文档版本：1.0。对应项目版本：0.1.0。更新日期：2026-10-20。

本文明确项目为什么做、当前做什么、后续如何演进。阶段一已经实现；阶段二、三为待开发需求，不代表当前具备相应功能。技术实现见 [方案设计](方案设计.md)。

## 一、项目背景与目标

作者需要持续发现热点、筛选值得写的主题、整理素材、完成文章，并向多个内容平台发布。当前这些工作分散在多个平台，重复检索和手工搬运消耗时间，热点与创作结果也难以关联。

内容工厂计划形成一条完整链路：

**关注主题 → 自动发现热点 → 人工选题 → 按作者风格生成初稿 → 作者审核 → 多平台发布。**

当前优先解决“发现什么、值得写什么”，同时保存稳定选题 ID 和来源，为后续自动化创作与发布提供基础。

## 二、用户与使用场景

首版服务单个内容创作者，运行在本机或私有环境。

| 场景 | 用户诉求 | 产品响应 |
| --- | --- | --- |
| 每日找灵感 | 无需逐个平台翻榜单 | 一页查看匹配关注主题的热点 |
| 跟踪特定方向 | 持续关注 AI 工具、大模型或商业动态 | 配置主题关键词和排除词，后台持续筛选 |
| 暂时不写 | 先留下值得关注的内容 | 收藏条目，后续随时回看 |
| 决定创作 | 将灵感变成明确的写作任务入口 | 加入“我的选题”，保留来源并支持导出 |
| 来源异常 | 不希望一个平台故障影响整个工作台 | 其他来源继续更新，故障与旧数据状态可见 |
| 后续自动化 | 写作和发布不应重复建设数据入口 | 以选题 ID 连接素材、初稿、审核与发布任务 |

页面目标是缩短日常链路：设置一次后打开即看；打开来源、收藏或加入选题各一次点击。低频配置集中在设置抽屉。

## 三、分阶段范围

| 阶段 | 业务目标 | 当前状态 | 主要产出 |
| --- | --- | --- | --- |
| 阶段一 | 根据关注主题自动发现热点，积累选题 | 已实现 | 热点列表、匹配原因、收藏、选题资料 |
| 阶段二 | 结合作者风格和可信素材生成文章初稿 | 待开发，已有接口契约 | 风格档案、素材、初稿、审核状态 |
| 阶段三 | 作者审核后发往多个平台 | 待开发，已有接口契约 | 平台发布任务、结果、重试与溯源 |

阶段一当前配置微博、知乎、百度、今日头条、抖音、B 站、Hacker News、IT之家、AIHOT、OpenAI 官方 RSS，共十个来源。它们包含公开热榜和资讯订阅，具体见 [数据源说明](数据源说明.md)。

### 主题业务规则

- 一个主题至少有一个非空命中词，命中任意一个即可进入该主题。
- 排除词优先，只排除当前主题的匹配，不影响其他主题。
- 匹配前统一大小写、全半角和空白；中文按子串匹配，英文/数字词按边界匹配。
- `AI` 不自动等于 `OpenAI`，需要显式配置相关词；当前不进行模型语义推断。
- 同一条内容可命中多个主题，但列表条目不因此重复。
- 当前一次可选择一个主题筛选；不支持多主题筛选器。
- 最多 20 个主题；主题名称 1–30 字；命中词和排除词各最多 30 个，每词最多 60 字。
- 修改主题后重新匹配已有内容；删除或禁用主题不删除收藏和已选题内容。

### 时间、排序与来源规则

- 默认每 10 分钟检查采集周期，可选择 30 或 60 分钟；实际请求仍遵守来源最小间隔。
- 每源每轮最多保存前 30 条，按来源实际返回量处理。
- 默认按发现时间窗口交错展示来源；也可按源内顺序排序，不计算跨平台统一热度分。
- 普通列表支持近 24 小时、7 天、30 天；收藏和选题库不受这个时间窗口限制。
- 观测时间表示本应用采集时间，不等于原文发表时间；缺失字段不伪造。
- 同源相同身份去重；不同平台对同一事件的报道暂不自动合并。

## 五、非功能需求

| 维度 | 要求 | 当前边界 |
| --- | --- | --- |
| 简洁性 | 高频操作集中在工作台，减少跳转 | 一个主界面、侧栏视图与设置抽屉 |
| 可追溯性 | 选题可追溯到来源和观测时间 | 标题、URL、来源、稳定 ID 持久保存 |
| 可靠性 | 故障隔离、重复采集幂等、重启恢复 | 单实例任务互斥、事务与持久化任务记录 |
| 可扩展性 | 平台差异封装在适配器中 | 已有采集、写作、发布接口边界 |
| 性能 | 浏览页面读取本地数据，不等待外部平台 | 大规模数据性能需另行验证 |
| 数据保留 | 普通历史自动清理，保留创作所需条目 | 快照、任务、事件仍按保留期清理 |
| 运行环境 | 无需模型密钥即可完成选题 | Node 24+、可写数据目录、常驻进程 |
| 访问边界 | 首版只面向受控本机或私有环境 | 尚未实现公网认证、多人权限和分布式协调 |

## 六、阶段二与阶段三需求

### 阶段二：作者风格初稿

以已选题内容为入口，支持作者样文和风格档案、可信素材获取、带引用的初稿生成、人工编辑与审核。任务需要可取消、可恢复，并记录模型、输入素材和风格版本。阶段流转拟为 `selected → drafting → review`。

现有热榜标题和链接不等于完整写作素材，因此全文获取、事实核对与引用管理需要在此阶段实现。

### 阶段三：多平台发布

以审核通过的文章为入口，按平台转换格式、使用各自账号授权、分别创建发布任务并记录结果。支持部分成功、失败重试、幂等控制和结果对账；一键发布不意味着各平台结果必须同时成功。

消息通知 Webhook 不视作文章发布。具体平台、账号授权方式和实际可发布能力需在开发该阶段时核实。

## 七、验收标准与验证依据

| 验收项目 | 通过标准 | 现有验证 |
| --- | --- | --- |
| 标签匹配 | 关键词 OR、排除优先、英文边界、归一化符合预期 | 固定样例自动测试 |
| 采集可靠性 | 单源失败不阻止其他源，超时实际取消请求 | 自动测试与历史实测 |
| 幂等 | 重复结果不新增同源重复条目，收藏和选题不被覆盖 | SQLite 自动测试 |
| 持久化 | 关闭并重开数据库后仍保留配置、收藏和选题 | 真实临时数据库测试 |
| 配置与查询 | 主题修改后旧内容重匹配，筛选结果符合条件 | 自动测试及 API 验收 |
| 选题操作 | 收藏、加入选题、导出和原文跳转可使用 | API 与浏览器验收 |
| 工程检查 | 测试、生产构建与类型检查通过 | 2026-10-20 提交前复核 |
| 外部来源 | 记录实际请求结果，不用模拟测试代替平台验证 | 2026-10-15 首轮十源实测通过；实时状态以运行实例为准 |

完整验证结果与未验证项见 [测试验证](测试验证.md)。长期稳定性、大规模负载、多人权限以及后续写作/发布不包含在已完成的验收结论中。

## 八、需求排除与风险

阶段一不承诺全网搜索、付费内容抓取、文章全文获取、语义聚类、自动撰稿、自动发布、团队协作或关机期间运行。

主要风险是来源页面/接口变化、Cookie 失效、垂直主题未进入热榜，以及上游维护策略变化。对应措施是独立适配器、清晰来源状态、失败重试和固定上游版本；需要补充新来源时按 [扩展开发](扩展开发.md) 接入。
