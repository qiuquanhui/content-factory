# 阶段一需求文档：按标签自动发现热点

版本：v0.1（待确认）。日期：2026-10-14。

## 1. 产品目标

作者设置关注标签后，系统在后台持续汇总各平台公开热榜，筛出相关条目，作者在一个页面浏览并收藏选题，为阶段二提供可追溯素材入口。

核心流程：**设置关注标签 → 自动获得相关热点 → 收藏值得写的选题**。日常打开页面即可浏览，不需要每天创建采集任务或进入多个平台。

阶段衔接：阶段一输出选题及来源；阶段二再引入作者样文、事实素材和初稿生成；阶段三再接入经作者审核后的多平台发布。通知消息推送和内容平台文章发布是不同能力，不能互相替代。

## 2. 建议范围与假设

| 项目 | 首版建议 |
| --- | --- |
| 使用者 | 单个作者；不包含团队协作 |
| 运行环境 | 本机或私有服务器常驻，页面关闭后后台仍运行；机器休眠、关机时不采集 |
| 首批平台 | 微博、知乎、百度、今日头条、抖音、B 站热搜，共六个目标源 |
| 采集范围 | 已支持的公开热榜条目，不是全网搜索、站内关键词搜索或完整文章抓取 |
| 调度 | 默认每 10 分钟一轮；支持 10/30/60 分钟；尊重各源更长的最小更新间隔 |
| 数据范围 | 从部署后开始累计；不承诺补齐部署前的历史热榜 |
| 费用 | 首版标签筛选不调用大模型；运行机器和网络由部署环境提供 |

上述为建议，待用户确认；六个平台目前只核实了代码适配，实际可用性由开发第一步 PoC 验证。小红书、微信公众号等不直接列入首版支持清单。

## 3. 功能需求

| 编号 | 优先级 | 功能 | 具体要求 |
| --- | --- | --- | --- |
| FR-01 | P0 | 管理关注标签 | 新建、编辑、删除、启停标签；填写名称、命中词和排除词；关闭或删除不删除已收藏选题 |
| FR-02 | P0 | 多平台自动采集 | 启用的源按调度后台运行；多个标签共用采集结果；无页面访问仍执行 |
| FR-03 | P0 | 规则筛选 | 对标题及源自带的可选摘要匹配，展示命中的标签和关键词 |
| FR-04 | P0 | 统一热点列表 | 标题、平台、源内榜单位置、命中标签、首次发现时间、最近观测时间、原文链接 |
| FR-05 | P0 | 筛选浏览 | 默认“我的关注”；可切换“全部热点”“已收藏”；支持平台、标签和最近 24 小时/7 天/30 天筛选 |
| FR-06 | P0 | 立即刷新 | 一次点击触发全局采集；执行中合并重复请求；60 秒防重复触发；不突破各源最小间隔 |
| FR-07 | P0 | 幂等与历史 | 同一源同一条目不重复新增；保存实际成功采集的榜单快照；跨平台条目保留各自来源 |
| FR-08 | P0 | 收藏选题 | 一次点击收藏/取消；保存选题 ID、标题、链接、来源、收藏时间；刷新和重启后保留 |
| FR-09 | P0 | 失败可见 | 单源失败不影响其他源；有旧数据则继续显示并标注过期，无旧数据则显示失败状态 |
| FR-10 | P0 | 简单设置 | 在侧边抽屉设置标签、源开关与采集周期；展示每源状态和最后成功时间 |
| FR-11 | P1 | 关键词临时搜索 | 在已采集本地数据中搜索标题，明确不是全网搜索；可在首版 P0 验收后增加 |

P0 为阶段一验收范围，P1 不影响 P0 交付。默认最多 20 个标签，每标签 20 个命中词与 20 个排除词；源数据按实际返回量展示，不伪造条数。

## 4. 标签匹配的确定规则

标签是作者的主题规则，不是平台自身分类标签。例：“人工智能”标签的命中词为 `人工智能、AI、OpenAI、DeepSeek、ChatGPT`，排除词为 `培训广告、卖课`。

1. 标签至少有一个非空命中词；多个命中词之间为 OR，任意一个命中即有资格进入该标签。
2. 排除词优先：命中该标签任意排除词，就不属于这个标签；不会自动排除它在其他标签中的匹配。
3. 匹配前做 Unicode NFKC、英文字母大小写与空白归一化。中文词按子串匹配；纯英文/数字词按字母数字边界匹配，避免 `AI` 命中 `chair`。`AI` 不自动等价于 `OpenAI`，需要显式配置别名。
4. 只使用标题和平台本来就返回的可选摘要；没有摘要时只匹配标题，不自动请求全文。
5. 同一条热点可命中多个标签，列表只展示一次并显示多个标签。
6. 同时选多个标签时取并集；未启用任何标签时“我的关注”提示设置标签，“全部热点”仍可查看。
7. 保存规则后，用保留期内的已有条目重新匹配，不要求等待下一轮抓取；过程中显示“正在更新匹配”，完成后展示新版本结果。
8. 首版不支持任意正则、隐式语义扩展或 AI 自动判断相关性，保证结果可解释、无模型调用成本。

注意：这个规则保证的是“已抓到的热榜中按关键词筛选”，不是保证找全某个行业的新闻。例如科技热点未进入平台热榜，首版就可能采不到。

## 5. 页面与使用链路

采用一个主页面、一个设置抽屉。首次使用从主页面打开设置，保存后自动触发一次采集；日常不重复引导。

```text
内容工厂                     更新于 14:30  [刷新] [设置]
我的关注 | 全部热点 | 已收藏
标签：全部  人工智能  科技  副业     平台：全部 ▾  时间：24小时 ▾
----------------------------------------------------------
某模型发布新版本                            ☆ 收藏
知乎 · 榜单第 3 位 · 人工智能 · 首次发现 14:10    查看原文 ↗
----------------------------------------------------------
某公司推出新产品                            ★ 已收藏
微博 · 榜单第 8 位 · 科技 · 首次发现 13:50        查看原文 ↗

底部状态：5 个源正常，1 个源异常（查看详情）
```

这是信息布局示意，不是最终视觉稿。标题也可直接打开原链接；收藏无需进入详情页。桌面每行清晰展示信息，手机使用单列列表。分页/加载更多建议每页 30 条。

默认排序为首次发现时间倒序，次序相同时按平台和源内榜单位置稳定排序。“榜单第 N 位”仅表示该源当次返回的位置，不能当作平台官方热度分或跨平台统一热度。

页面顶部“更新于”表示本应用最近一轮完成时间；具体源状态提供真正的最后成功采集时间。不得仅因为读到了缓存就显示“平台刚刚更新”。

## 6. 异常与边界

| 场景 | 用户看到的结果 | 系统行为 |
| --- | --- | --- |
| 标签没有匹配结果 | “最近 24 小时暂无相关热点”，可切换全部热点 | 不用无关内容填充 |
| 某源超时/403/解析失败 | 对应源异常，有旧数据则标注其采集时间 | 保留最后成功数据，其他源正常落库 |
| 所有源失败 | 明确显示采集失败和上次成功时间 | 不显示成功提示，不清空历史和收藏 |
| 返回 HTTP 200 但结构不符 | 显示源异常 | 不将其当成功或空榜 |
| 返回合法空列表 | 显示“本轮返回空榜，旧数据仅供参考” | 记录 empty，旧条目不标为当前在榜，连续空榜进入排查 |
| 连续点击刷新 | 显示已有任务进度/冷却提示 | 不叠加重复采集 |
| 正在采集时修改标签 | 标签保存成功，展示匹配更新状态 | 数据采集与匹配版本独立，避免旧规则覆盖新规则 |
| 服务重启 | 标签、收藏和历史仍在 | 将中断任务标记为 interrupted，启动后补一次到期采集 |
| 机器关闭后重开 | 展示上次时间，再更新到当前 | 不补发休眠期间每一个错过的任务 |
| 外部条目无发布时间/摘要/热度 | 对应字段不展示 | 不使用发现时间冒充发布时间 |

首版只收集公开热榜需要的元数据和链接；不要求作者提供发布账号密码，也不引入验证码绕过或付费内容采集流程。

## 7. 非功能要求

- 易用性：配置一次后打开即看；从列表到原文/收藏各 1 次点击；不设置复杂菜单和独立任务管理页面。
- 数据可追溯：每项有平台、链接与采集时间，收藏保留原始来源。
- 可靠性：单源故障隔离；读数据不依赖实时平台请求；采集幂等，重启不丢数据。
- 响应目标：约 4 核/8 GB、本地 SSD、单用户、保留不超过 10,000 条条目的验收基线下，预热后的热点首屏在 2 秒内显示；外网采集耗时单独统计。
- 时区：界面与调度采用 Asia/Shanghai，数据库时间统一 UTC。
- 保留策略：普通条目与榜单快照默认保留 30 天；收藏条目的标题、链接和来源保留到主动取消收藏后再按策略清理；该条目的历史榜单不无限保存。
- 部署：优先一个常驻应用和一个持久化目录，无必须 Redis、消息队列或大模型服务。
- 访问范围：默认监听本机/私有环境。若要开放公网多用户，另行明确登录和访问控制范围。

## 8. 明确不纳入阶段一

文章全文抽取、作者样文学习、写作风格模仿、初稿生成、自动配图、多平台文章发布、平台账号托管、团队权限、跨平台语义事件合并、智能热度评分、实时大屏、手机通知和复杂趋势分析。

保留固定的选题 ID 和来源即可衔接阶段二，不提前建设写作与发布系统。阶段二还需补充可靠事实素材，不能仅凭热榜标题生成未经核实的完整文章。

## 9. 验收标准

以下为开发完成后应执行的验证，当前尚未执行。

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| AC-01 | 首次使用 | 创建 2 个标签并保存，主页面可看到匹配结果和原因；若现场无相关热点，使用明确标记的测试数据验证筛词 |
| AC-02 | 六平台接入 | PoC 中六个约定源各三轮间隔 10 分钟成功；有效条目具备标题、HTTP(S) 链接和源内位置；正式验收再做一轮六源实测 |
| AC-03 | 无人值守 | 关闭浏览器、服务常驻 30 分钟，日志与任务记录证明至少完成 3 次默认周期的到期调度；不依靠手动刷新 |
| AC-04 | 标签精确性 | OR、排除词、大小写、英文边界、多标签去重和规则修改的固定测试样例全部通过 |
| AC-05 | 幂等 | 同一批结果连续入库两次，条目数与收藏数不重复；实际不同采集批次保留独立观测 |
| AC-06 | 局部失败 | 注入一个源超时/403/格式错误，其余源继续更新，失败源旧数据带时间标记 |
| AC-07 | 全部失败/空榜 | 页面能区分全部失败、合法空榜和没有命中；不会把缓存或空结构误报为新鲜数据 |
| AC-08 | 收藏持久化 | 收藏一项，刷新页面并重启服务后仍在，取消收藏后状态正确 |
| AC-09 | 数据时效 | 平台请求时间、任务完成时间、缓存时间含义可区分；不伪造发布时间或热度 |
| AC-10 | 简洁交互 | 日常查看无需进入设置；查看原文、收藏各 1 次点击，桌面和手机宽度均可用 |
| AC-11 | 本地性能 | 在声明的验收基线下重复打开预热首屏 10 次，每次在 2 秒内显示本地结果；记录结果，不含外部站点采集耗时 |
| AC-12 | 清理与恢复 | 超过保留期的普通数据可清理，收藏元数据仍可用；备份文件在停止写入后可恢复 |

如果平台上游临时失效，模拟测试只能证明我们自己的逻辑，不能代替该源真实接入验收；必须记录阻塞并提出修复或范围调整供用户确认。
